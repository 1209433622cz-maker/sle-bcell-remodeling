# 四、正文只发现两处值得继续动，不应该再大改

目前 Abstract 已经非常成熟：它在一段中同时给出了 identity failure、composition boundary、external source-label-defined IFN replication、failed corrected remapping 和 observational TF ceiling，最后落到“process-level > hard state assignment”。这个 Abstract 我现在建议 **KEEP，不再继续压缩**。

第一处小修位于 Introduction 最后一段。目前写：

> `which B-cell features survive increasingly stringent reconstruction and validation`

虽然这里的 `validation` 是 generic 用法，本身不算错误，但经历了上一轮严格的 evidence-class lock 后，读者第一次顺读时仍可能把它误读成“每一层都有 independent validation”。

因此我给 candidate 改成：

> **`which B-cell features survive increasingly stringent reconstruction and replication tests`**

这与目前全稿建立的 terminology hierarchy 更一致。原句位于 Introduction 到 Results 的过渡位置。

第二处是真正的 prose redundancy：Discussion 最后一段已经完成中心总结后，又重复列出：

`not a universal B-cell taxonomy, generalized B_ASC expansion, causal regulator, unique upstream stimulus or established clinical utility`

这些 boundary 前面已经分别由 composition、regulator、clinical implication、limitations 各自明确拥有。

最终收束更适合改成：

> **`Retaining the failed reconstruction and calibration criteria narrows, rather than weakens, the conclusion: the data support a bounded process-level interferon association within explicit identity and transfer limits.`**

我认为这个版本明显更强。它不是“删除免责声明”，而是把已经证明过的五个否定重新压缩成论文自己的正面科学命题。

其余 Discussion 我**不建议继续 prune**。尤其开头的“difference in reproducibility across biological layers, not a new B-cell taxonomy”和后面的“tempting but unsupported narratives”虽然和 Results 有语义重合，但承担的是 interpretation/synthesis，而不是重复报告数据，应保留。

# 五、这轮我没有去修改冻结 Source Data

这一点非常重要。

S3/S5 的正确实现方式不是删除 CSV 行，也不是 Photoshop/crop 旧图，而是：

**冻结 Source Data保持 byte-identical → plotting code只读取要保留的 source panels → 重新排版输出 → 单独产生 display-panel mapping。**

也就是说：

`S3b → final S3a`
`S3c → final S3b`

以及：

`S5a/b/c → final S5a/b/c`

而原 S3a/S3d/S5d 数据依然保留在 provenance 中。

这正好符合你一直强调的原则：**优先从源数据重跑图，而不是修改已有结果输出对象。**

GitHub 当前 plotting style contract 仍规定 6.8-inch/约 170-mm working width、6-pt base font，并优先 Arial/Helvetica；我也据此为 S3/S5 写了 source-redraw runner。

但我**没有在这个环境伪装生成最终图**：这里无法保证真正的 Arial，而你上一轮已经明确拒绝 Arimo fallback。新 runner 因此设计为：

**如果找不到真正 Arial，就直接报错退出，而不是偷偷替代字体。**

这是比输出一个“看起来差不多”的候选图更严格的处理。
