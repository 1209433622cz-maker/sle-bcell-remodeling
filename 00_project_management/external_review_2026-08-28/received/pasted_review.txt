## 一、这次纠错是必要的，而且处理方式是正确的

我复核后确认，旧 C9 有两个真正的技术阻断问题。

第一，旧 reference mapper 的 reference cells 是先截取约 601 个 mapping features，再以这些 selected-feature counts 作为 library-size denominator；external cells 却是按**全转录组 library total**做 log1p(CP10K) 再截取 features。也就是说 reference 与 external feature vectors 原先并不在同一归一化尺度。纠错契约已经把它改成两边统一使用 full-library totals，并明确禁止改 feature set、alpha grid、confidence grid、seed 或 gate 来“救结果”。

第二，旧 elastic-net 的 0.95 confidence threshold 实际没有满足冻结的双 state precision 门槛，却允许 diagnostic fallback 继续授权 outcome access。纠错后的 gate 已改成真正的 fail-closed：B_CONV precision 很高，但 B_ASC precision 只有 **0.8852097**，因此 formal decision 是 HOLD，`outcome_unlock_authorized=false`。

所以目前绝不能再写：

> “source-label-agnostic GSE135779 validation replicated the IFN result.”

现在准确的表述只能是：

> **Source-label-defined GSE135779 replication remains; source-label-independent external robustness remains unresolved because corrected reference calibration did not meet the frozen B_ASC precision criterion.**

这一点最新 README 已经写对了。

## 二、不要试图把 C9R HOLD 调成 PASS

这是现在最重要的方法学纪律。

虽然中心外部 IFN 分析真正关心的是 B_CONV，而且 corrected elastic-net 的 B_CONV precision 达到约 **0.99645**，但不能在看到旧 C9 outcome 以后，把原本的“双 state ≥0.90”改成“只要求 B_CONV ≥0.90”。

同样不能：

* 把 0.90 改成 0.88；
* 丢掉 elastic-net，只保留通过的 centroid；
* 扩大 alpha/confidence grid；
* 换 seed；
* 换 feature set；
* 新增第三 mapper，直到某个算法 PASS；
* 再调用原来已经看过的 positive C9 outcome 来选择模型。

这些都会把一次高质量纠错变成 outcome-informed rescue。

如果未来 reviewer 真正要求 source-label-independent external corroboration，正确路径是**新的预先冻结验证设计或另一个独立队列**，而不是修改 C9R gate。
